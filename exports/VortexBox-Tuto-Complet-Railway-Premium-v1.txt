VORTEXBOX - TUTO COMPLET RAILWAY
Installation production pas a pas de votre site VortexBox
Date: 09/03/2026

============================================================
1) OBJECTIF
============================================================
Publier le site VortexBox sur Railway avec:
- un backend Node.js actif (server.js)
- conservation des donnees admin et uploads
- mise a jour simple depuis GitHub

Projet GitHub utilise:
- Repository: Vortex-hub-fr/vortexbox
- Branch: main

============================================================
2) PRE-REQUIS
============================================================
- Compte Railway actif
- Compte GitHub connecte a Railway
- Projet local propre dans:
  /Users/brunosoler/Documents/Playground

Commandes locales utiles:
- cd /Users/brunosoler/Documents/Playground
- git status

============================================================
3) CREER LE SERVICE RAILWAY
============================================================
Etape 1:
- Railway > New Project > GitHub Repository
- Choisir: Vortex-hub-fr/vortexbox

Etape 2:
- Le service se cree (nom: vortexbox)
- Ouvrir la carte du service > onglet Settings

Etape 3 (important):
- Start Command: npm start
- Root Directory: laisser vide

============================================================
4) VARIABLES D'ENVIRONNEMENT
============================================================
Dans Railway > Service > Variables, ajouter:

Variables minimales:
- NODE_ENV=production
- HOST=0.0.0.0
- PORT=${{RAILWAY_PORT}}

Si vous utilisez email OTP:
- MAIL_FROM=VortexCore@outlook.Fr
- SMTP_HOST=smtp.office365.com
- SMTP_PORT=587
- SMTP_USER=VortexCore@outlook.Fr
- SMTP_PASS=<mot_de_passe_application>

Si vous utilisez IA:
- OPENAI_API_KEY=<votre_cle>
- OPENAI_MODEL=gpt-4.1-mini

Note:
Ne mettez jamais vos mots de passe en dur dans le code.

============================================================
5) VOLUMES PERSISTANTS (OBLIGATOIRE)
============================================================
Sans volumes, vous perdrez des donnees apres redeploiement.

Ajouter 2 volumes:
- Volume 1 monte sur /app/uploads
- Volume 2 monte sur /app/data

Verification:
- Upload image test dans l'admin
- Redepoyez
- Verifiez que l'image est toujours presente

============================================================
6) NETWORK / DOMAINE
============================================================
- Settings > Networking > Generate Domain
- Port cible: 8080
- Generer le domaine public

URL type:
- https://vortexbox-production.up.railway.app

Domaine perso (optionnel):
- Networking > Custom Domain
- Ajouter votre domaine (ex: vortexbox.org)
- Configurer DNS chez votre registrar

============================================================
7) DEPLOIEMENT INITIAL
============================================================
Railway deploie automatiquement apres connexion GitHub.

Verifier dans Deployments:
- Build: OK
- Runtime: OK
- Health: OK

Endpoint de sante:
- /health

============================================================
8) MISE A JOUR DU SITE (WORKFLOW SIMPLE)
============================================================
Depuis votre Mac:

1. cd /Users/brunosoler/Documents/Playground
2. git add .
3. git commit -m "MAJ VortexBox"
4. git push origin main

Railway redeploie automatiquement la branche main.

Si aucun changement:
- git commit peut repondre "nothing to commit"
- dans ce cas, faire directement git push origin main

============================================================
9) CHECKLIST APRES DEPLOIEMENT
============================================================
- Connexion utilisateur: OK
- Connexion administrateur: OK
- Bouton Administrateur visible uniquement pour admin: OK
- Upload images/videos: OK
- Donnees admin conservees apres reload: OK
- Jaquettes jeux visibles: OK
- VortexBot visible sur toutes les pages: OK

============================================================
10) DEPANNAGE RAPIDE
============================================================
Probleme: la page revient sur connexion
- Verifier la session utilisateur
- Verifier les variables d'environnement
- Verifier les droits admin cote code

Probleme: donnees perdues
- Verifier volumes /app/uploads et /app/data
- Verifier que le service Railway utilise bien ces mounts

Probleme: upload KO
- Verifier les formats autorises
- Verifier taille fichier
- Verifier permissions du dossier uploads

Probleme: deploy KO
- Ouvrir Deployments > View Logs
- Corriger l'erreur puis repush

============================================================
11) BONNES PRATIQUES SECURITE
============================================================
- Changer regulierement le mot de passe admin
- Utiliser un mot de passe applicatif pour SMTP
- Ne pas exposer les secrets dans Git
- Sauvegarder regulierement via l'onglet Sauvegarde admin
